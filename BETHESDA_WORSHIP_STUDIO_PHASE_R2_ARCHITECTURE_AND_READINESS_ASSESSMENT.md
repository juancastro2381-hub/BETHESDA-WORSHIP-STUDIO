## 3. Current Architecture

Bethesda Worship Studio is structured as a modular monorepo without formal workspace package boundaries:

1. **Backend (`backend/src/`):** Fastify `5.12.5` ESM TypeScript API compiled via `backend/tsconfig.build.json` to `dist/backend/src/server.js`.
   - **Interfaces (`interfaces/http/`):** 14 route plugins (`health`, `auth`, `users`, `user-preferences`, `songs`, `setlists`, `worship-services`, `documents`, `conversion`, `audio`, `ingestion`, `omr`, `multitrack`, `realtime`), custom `AuthGuard`, `DualRateLimiter`, `ErrorHandler`, Swagger UI.
   - **Application (`application/`):** Services for Auth/JWT/Reset/Invitation, Catalog/Versioning/Completion, Setlists/Worship Services, Conversion Jobs/Worker/Retention, Audio Preservation/Transcription, Universal Ingestion, Documents, OMR, Multitrack, Realtime SSE, Stream Tickets.
   - **Domain & Repositories (`domain/`, `repositories/`):** Drizzle ORM `0.39.3` (`pg` pool `max: 20`) targeting 21 PostgreSQL tables, local FS storage adapters across 4 folders, `PythonAudioWorkerBridge`, and `CanonicalSerializer`.
   - **Workers / Queue (`infrastructure/queue/`):** `pg-boss` v12.38.1 queue `conversion-jobs` consumed **in-process** by `ConversionWorker` inside `server.ts`.
2. **Shared Musical Core (`frontend/src/core/`):** Pure TypeScript domain model (`CanonicalMusicPayload` at 480 TPQN), music theory (`Pitch`, `Chord`, `EnharmonicSpelling`, `TranspositionEngine`), importers (`MusicXmlImporter`, `ChordProImporter`, `AsciiTabImporter`), exporters (`MusicXML`, `ChordPro`, `MIDI`, `Tablature`, `LyricsOnly`), `ProjectionService`, `StandFormatCapabilityResolver`, OSMD/AlphaTab/LeadSheetDOM rendering adapters, API client (`BethesdaApiClient`), auth token memory manager, IndexedDB offline manager, and pure state orchestrators.
3. **Frontend (`frontend/src/`):** React `19.3.0` + Vite `8.3.0` SPA without client router (`App.tsx`), 3 React contexts (`Theme`, `Auth`, `Offline`), 35 UI components (`MusicalWorkspace`, `ConversionCenterWorkspace`, `SetlistsModal`, `SetlistDetailEditor`, `FormatCompletionWizardModal`, `VisualDocumentStand`, `UserManagementModal`), OSMD `^2.1.2` + AlphaTab `^1.8.4`, single `9,344`-line `index.css`, and `public/sw.js` Service Worker.
4. **Python Audio Worker (`workers/audio_worker/`):** Invoked over stdin/stdout JSON Lines IPC v1.0 (`PING`, `INSPECT_AND_VERIFY_AUDIO`, `ANALYZE_AUDIO`) using `numpy`, `pydantic`, and `imageio-ffmpeg` (bundled GPLv3 FFmpeg binary).

## 5. Architectural Weaknesses

1. **Cross-Layer Build & Deployment Coupling (`VERIFIED | High`):** **30 backend files** (`17` production files = `78` imports, `13` tests = `23` imports) reach across directory boundaries into `../frontend/src/core/`. `backend/tsconfig.build.json` therefore emits a nested `dist/backend/src/server.js` + `dist/frontend/src/core/...` tree plus manual `fs.cpSync` migration copying (`backend/package.json:8-9`), preventing independent backend packaging/containerization.
2. **Hard Single-Node Process-Local State (`VERIFIED | Critical`):** **7 stateful subsystems** live exclusively in API process RAM (`DualRateLimiter` Maps ×3, `globalStreamTicketService` Map, `globalRealtimeSessionManager` Maps/Subscribers, `globalAudioService` lock/recovery Maps, `DocumentService.registeredDocuments`, `MultitrackService.sessions` stale L1 cache, `OmrService.proposals` unbounded cache). Unused `REDIS_URL` sits in `config/env.ts:62`.
3. **14× Manual DI Duplication & Redundant DB Queries (`VERIFIED | Medium`):** `JwtTokenService`, `DrizzleUserRepository`, and `AuthGuard` are re-instantiated across `app.ts` and every route plugin (`ingestion.routes.ts:141` forgets `env.JWT_ACCESS_EXPIRES_IN`); `audio.routes.ts:763` creates `new DrizzleSongRepository()` per HTTP request; `realtime`, `multitrack`, `user-preferences`, and `auth /me` run duplicate `userRepo.findById` queries after `AuthGuard` already fetched the user; `multitrack.routes.ts:191-204` executes N+1 queries.
4. **Monolithic Frontend Bundle & God Components (`VERIFIED | High`):** Zero `React.lazy()` calls produce a `3,262,555-byte` (~3.26 MB) initial JS payload (`OsmdAdapter` + `AlphaTabAdapter` eager via **3 separate `RendererRegistry` singletons**) and a `9,344`-line global `index.css`; UI concentrates into `ConversionCenterWorkspace.tsx` (2,967 lines, 42 `useState`, 101 inline styles), `SetlistsModal.tsx` (1,224), `SetlistDetailEditor.tsx` (1,222), `FormatCompletionWizardModal.tsx` (1,198), `MusicalWorkspace.tsx` (989), and `UserManagementModal.tsx` (843).
5. **Half-Wired Backend Surface & Unowned Orphan Modules (`VERIFIED | High`):** Only **`51/109` (46.8%)** of HTTP routes are called by mounted UI (`66/109` in `api-client.ts`), while `ingestion.routes.ts` (0/6), `omr.routes.ts` (0/7), `multitrack.routes.ts` (0/6), `realtime.routes.ts` (0/9), and onboarding/recovery (`/accept-invite`, `/forgot-password`, `/reset-password`) are completely detached, leaving dead links in admin invites (`UserManagementModal.tsx:177,202`).
6. **Single-Tenant DB Schema & Fragmented Local Storage (`VERIFIED | High`):** `20/21` tables have no `community_id`/`tenant_id` or PostgreSQL RLS (`background_jobs.tenant_id` hardcodes `'bethesda-default'`), `idx_setlists_single_active` is DB-global, and 4 local storage classes resolve paths relative to `process.cwd()`.

## 8. Musical Domain Integrity Review (Section 7 — Explicit Answers to Questions 1–12)

1. **Is canonical musical information protected from accidental destruction?** **Partially — NO at ingestion/DB lifecycle (`Critical`, `VERIFIED`):** Core `ProjectionService` does not mutate `CanonicalMusicPayload` in memory, *but* `song_versions.song_id` uses `ON DELETE CASCADE`, `song_versions` has zero DB immutability trigger (`audit_logs` too), `MUSICIAN` can replace the active version of `APPROVED` songs, and importers (`MusicXmlImporter` parts `2..N`, `WrittenNotesIngestionAdapter` bar overflow) drop notes on ingest.
2. **Is imported source material distinguishable from generated or interpreted content?** **Partially — Severe Gaps (`High`, `VERIFIED`):** `AudioTranscriptionService` and `OmrService` schema track `is_ai_draft`/`evidenceStatus`, *but* `OmrService.commitToCanonicalSong` omits canonical `metadata`, `version-repository.ts:128` & `song-repository.ts:210` mislabel `MIDI/PDF/AUDIO` as `'MUSIC_XML'`, `ConversionJobService.commitJobToCatalog:623` uses target format as source format, and `ConversionTransformer` strips `evidenceStatus`/`confidence`.
3. **Do conversion operations preserve provenance?** **No (`High`, `VERIFIED`):** `ConversionJobService.commitJobToCatalog` drops key/BPM/meter summary fields and rewrites `sourceFormat` to `targetFormat`; `ConversionTransformer` erases AI uncertainty metadata; frontend `ProvenanceManager` hashes via non-crypto FNV-1a and stamps `'2026-09-19T00:00:00.000Z'`.
4. **Can musical data integrity be verified?** **Partially (`High`, `VERIFIED`):** `CanonicalModelValidator` runs structural checks, *but* `CanonicalSerializer` skips `TemporalValidator` (`:32, 92`), so broken ties, same-voice collisions, and negative/out-of-range timings persist silently; pickup measures create validator contradictions; `Pitch.midiNumber` & `Chord.parse` corrupt pitch/harmony even on valid payloads.
5. **Can the system detect incomplete musical content?** **Design-level Yes, Runtime Inconsistent (`High`, `VERIFIED`):** `TempoMap.isUnresolved`, nullable measure fields, and `StandFormatCapabilityResolver` exist, *but* 8 adapters/schemas silently inject fake `C Major`, `120 BPM`, `4/4`, filler rests, or note `'C'` before validation runs, and `WorkspaceOrchestrator` bypasses `StandFormatCapabilityResolver`.
6. **Is generated/interpreted content improperly treated as authoritative?** **Yes (`Critical`, `VERIFIED`):** Approving 1 format in `MusicalContentCompletionService` sets global `APPROVED`, unlocking all 4 formats in `StandFormatCapabilityResolver`; `completion` pre-stamps ChordPro drafts `HUMAN_VERIFIED`; `DocumentService`, `UniversalIngestionService`, and `IngestionPersistenceService` commit heuristic/warning outputs directly as `status: 'APPROVED'`.
7. **Are different reading formats projections of a shared canonical representation or duplicate sources?** **Intended Projections, Violated in 2 Places (`Critical`, `VERIFIED`):** `ProjectionService` drives Sheet/LeadSheet/Lyrics/Tab from one canonical object, *but* `LyricSyllable.chordAbove` duplicates `Measure.chords` untransposed/uncapoed in `LeadSheetDomAdapter` & `ChordProSerializer`, `Tablature` projection ignores `transpositionSemitones`, and `DocumentService.convertAndSaveSong:336` copies `lyricsOnly` into `song_metadata.notes`.
8. **Does song versioning preserve historical musical content?** **Application-Level Only (`High`, `VERIFIED`):** App writes insert new rows, *but* zero PostgreSQL immutability trigger prevents `UPDATE`/`DELETE`, `ON DELETE CASCADE` wipes history on song delete, unlocked `max(versionNumber)+1` risks race failures, and `is_current` lacks a partial unique index.
9. **Are transformations reversible where required?** **Broken in Common Cases (`Critical`, `VERIFIED`):** MusicXML minor-key export emits `<mode>natural_minor</mode>` -> re-imports as relative Major (`Am->C`); `Pitch.midiNumber` shifts `Cb`/`B#` by 12 semitones; `Chord.parse` (`Csus2->Csus4`, `Cmaj->Cm`, `Cmaj9->Cmaj7`); chromatic transposition spellings lose original borrowed chords (`Ab` in C -> `A#` in D); MIDI export doubles bar `startTick >= bar 2`.
10. **Does the architecture support musicians choosing different reading formats for different instruments?** **Yes Architecturally, Broken in Key Details (`High`, `VERIFIED`):** `UserViewPreferences`, `InstrumentRegistry`, and `ProjectionService` support per-instrument profiles, *but* `Tenor Sax` transposes `+2` instead of `+14`, `STANDARD_NOTATION` routes to `AlphaTab` emitting `0.1`, `AlphaTabAdapter` ignores post-init `staveProfile` switches, `InstrumentSelector` breaks `bass`/`drums` pills, and `music-stand-controller` omits `GRAND_STAFF: 'SCORE'`.
11. **Can the architecture preserve uncertainty when information cannot be reliably extracted?** **At Leaf Model Level Yes, Broken in Pipelines (`Critical`, `VERIFIED`):** Core types model uncertainty cleanly, *but* ingestion/completion/UI layers overwrite null/uncertain states with fabricated `C / 120 / 4-4`, `AlphaTex` emits `0.1`, PDF extractor defaults `detectedKey` to `'C'`, and `VisualDocumentStand:313` displays `"GRANDE ES TU FIDELIDAD"` on broken images.
12. **Is human validation appropriately integrated into workflows?** **Only in `OmrService`; Bypassed Elsewhere (`Critical`, `VERIFIED`):** `OmrService` enforces draft -> flag check -> commit + DB audit log (minor gap: `UNPARSED_CHORD` soft-drop), whereas `POST /songs`, `PUT/POST versions`, `DocumentService`, `UniversalIngestionService`, and `ConversionJobService.commitJobToCatalog` (`REVIEW_REQUIRED`) bypass human review gates.

### Silent Musical Corruption Summary
The highest-priority musical dangers are **silent mutations** where tests appear green or endpoints return `200/201` while music theory/timing is wrong: `Pitch.midiNumber` (`R2-F01`), `Chord.parse/toString` (`R2-F02`), `midi-serializer.ts:261` (`R2-F03`), Tablature ignoring transposition & `chordAbove` duplication (`R2-F04`), minor key fifths/XML `<mode>` mutations + MusicXML parts `2..N` discard (`R2-F05`), and measure-relative vs absolute lyric ticks (`R2-F08`).

## 9. Canonical Data Review

- **Time Model (`480 TPQN`):** Sound integer tick design, but `LyricSyllable.tickOffset` uses measure-relative `[0, measureDuration)` coordinates while `Note.startTick` and `ChordEvent.startTick` use song-absolute cumulative ticks — causing alignment breaks from bar 2 onward across 6 renderers/serializers (`R2-F08`).
- **Simultaneity & Tupleting:** Simultaneous chord notes rely on expando `(note as any).chordId` or `notationMetadata.tablature.chordId` rather than a top-level serialized field, causing JSONB round-trip collisions in `AsciiTabImporter` and missing `chordId` in `MusicXmlImporter` / `MidiIngestionAdapter` (`R2-F05`); `Rest` lacks `notationMetadata`, preventing tuplet rests; `Voice.calculateTotalDurationTicks()` sums simultaneous chord notes instead of max-per-chord group (`R2-F09`).
- **Pickup Bars & Modulations:** `TemporalValidator` reads unserialized `(measure as any).isPickup`, `CanonicalModelValidator` strictly rejects shorter pickup durations, and `ProjectionService`/`ConversionTransformer` overwrite all measures with `measures[0]` key signature, erasing mid-song modulations (`R2-F09`, `R2-F10`).
- **Metadata Governance:** `CanonicalMusicPayload.metadata` is an untyped, shallow-frozen `Record<string, unknown>`, allowing per-format approvals, `isAiDraft`, and `sourceFormat` to be dropped or inconsistently populated across services (`R2-F07`, `R2-F10`).
